# 多端同步开发

React 源码集中在 `packages/app/src`，无需分别维护桌面与移动 UI。安装和平台依赖见 [本地开发](DEVELOPMENT.md)。

## 一个前端服务，多个客户端

需要同时调试时使用独立终端：

```bash
# 终端 1：保持运行
pnpm dev:web

# 终端 2：桌面客户端
pnpm dev:desktop

# 终端 3：macOS 上的 iOS 模拟器
pnpm dev:ios
```

也可在终端 3 使用 `pnpm dev:android`。每个原生启动过程确认 1420 上的工作区标识后复用前端；退出其中一个客户端不会主动结束另一个终端启动的前端。单端开发直接运行目标平台命令即可。

若由第一个原生客户端启动前端，退出该启动进程可能同时停止其子进程；长期并行调试推荐将前端独立运行。不同工作区不能共用同一个 1420 端口，脚本遇到不匹配的服务会退出并提示。

## 哪些改动需要重启

| 修改 | 处理 |
| --- | --- |
| React、CSS、i18n | Vite 热更新，检查不同屏幕宽度 |
| 根目录 `.env.local` | 在原终端重启前端 |
| Rust、原生权限与安全区 | 等待 Tauri 重编译，必要时重启原生客户端 |
| iOS `project.yml` | 结束当前构建，`pnpm init:ios` 后重新启动 |
| Android 生成配置 | 结束当前构建，再运行平台脚本应用共享设置 |
| pnpm / Cargo 依赖 | 更新并保留锁文件，重新安装或编译 |

前端开发可以并行，原生打包建议逐个平台执行：Cargo 可能等待共享缓存锁，多个构建还会同时写入 Web `dist` 或移动工程目录。不要在构建运行时执行清理或重新初始化。

## 提交前检查

```bash
pnpm check
pnpm build:web
```

再对涉及的平台检查登录恢复、搜索输入法、键盘操作、分页、深浅主题和四种语言。修改 iOS 安全区时须在模拟器/真机上切换设置并滚动验证；浏览器视口截图不能替代原生行为。
