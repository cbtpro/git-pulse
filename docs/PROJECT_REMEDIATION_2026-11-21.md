## iOS 底部空白修复

实现提交：`7175d1f`；原生验收提交：`6d516c6`。

iPhone 15 Pro Max / iOS 17.4 模拟器实测：原生 WebView、父视图和滚动视图均为 `430×932`，但网页初始高度为 `839`，刚好缺少顶部 `59` 与底部 `34`。因此不是简单的导航 padding 重复相加。仅调整根页面的最小高度后，网页和导航底边恢复为 `932`，无需修改原生视图 frame。

最终只对原生 iOS 的 `html/body` 设置 `min-height: 100vh`，让内部动态高度不再基于过短文档继续缩小。网页浏览器与 Android 保持原有布局，安全区开关继续控制内容留白。观察到的行为与 [WebKit 210009](https://bugs.webkit.org/show_bug.cgi?id=210009) 及 [254868](https://bugs.webkit.org/show_bug.cgi?id=254868) 描述的问题一致；这里依据实际测量选择修复，不把关联缺陷记录当作所有版本的验证结论。

浏览器布局回归验证开关对应的导航高度为 `100→66→100`，底边保持不变。模拟器冷启动后的前后截图和几何数据位于 `review-artifacts/safe-area/`。原生 XCTest 已通过真实安全区开关与完整软键盘出现/关闭后的底部位置验证；测试要求键盘高度大于 200 点，排除只出现输入附件栏的假阳性。

## 顶层菜单与滑动返回

实现提交：`f17d52a`。

底部菜单和桌面侧栏统一标记顶层分区切换。切换时只重置交互返回可使用的历史范围，不清理页面实例，也不改写浏览器历史。分区首页不会通过滑动切到前一个菜单；进入分区内的详情、设置或目录后，可以返回该分区内的上一页。仓库归属沿用当前历史记录的真实来源，避免同一仓库从搜索、收件箱等不同入口打开时返回错误分区。

测试覆盖菜单切回后原 DOM、输入和滚动保留；当前分区内完成/取消返回；在分区首页继续滑动不切菜单；同仓库不同来源；浏览器前进/后退不重复执行旧的菜单切换标记；外部导航打断正在进行的手势。浏览器工具栏与 Android 系统返回继续使用实际历史，iOS 页内交互返回按上述分区边界执行。

旧原生 GestureTests 曾把“设置→点搜索菜单→滑回设置”写成通过条件，本轮按用户明确的新要求反转该断言，增加分区内返回和根页面不跨菜单验证。没有用删除手势功能或销毁缓存规避问题。

## 实现边界

账号库原生锁保护同一应用进程的多个 WebView；当前没有独立原生进程间锁。Web/Android 的存储仍使用 IndexedDB 与 Web Crypto，未改为 Android 硬件 Keystore。新增原生命令需要重新构建应用，单独刷新前端不能更新 Rust 能力。

下载的 Token 仅用于 GitHub API 请求，不转发到签名下载地址。直接流上限为 512 MiB，未完成文件在断流、超限或任务销毁时清理；完成缓存由后续下载清理超过 24 小时的内容。页面未提供取消按钮，路由切换不会主动取消下载。测试覆盖本地响应与平台编译，未使用真实私有仓库附件验证系统分享。

原审计报告保留历史基线与复现记录；其中“缺陷存在”的断言不能用于当前验收。当前回归使用 `scripts/qa/vault-concurrency.mjs` 和 `scripts/qa/resource-consistency.mjs`，断言已经修复后的行为。
